# REUMLAB · MELIQ MVP 구축 역량 요약

름랩은 사용자 화면만 제작하는 방식이 아니라 **회원, Backend, Database, Admin을 함께 구성하여 실제 운영 가능한 Web/Mobile 서비스**를 구축해 왔습니다. 아래 3건은 MELIQ MVP가 요구하는 구조 — 사용자 서비스 · 관계형 DB · 인증/권한 · 관리자 운영 화면이 하나의 백엔드로 연결되는 형태 — 를 실제로 구현한 사례입니다.

---

### 학우너 (Hakwooner) — 소비자 앱 + 사업자 ERP

학원 검색·상담을 제공하는 Flutter 사용자 앱과, 원장이 원생·수업·수납·인사를 관리하는 Next.js 기반 ERP(126개 화면)를 하나의 PostgreSQL 위에서 운영하는 양면 플랫폼입니다. 테이블 222개, 마이그레이션 310단계, RLS 정책 459건 규모의 스키마를 직접 설계·운영했습니다.

**MELIQ 직접 관련** — 거리·과목·목표·수업형태·예산·리뷰 6개 축에 가중치를 두어 합산하는 **규칙 기반 추천 엔진**을 구축했습니다. 결과는 0~100으로 정규화한 적합 점수와 사용자용 라벨로 환산되며, 점수를 만든 근거를 사람이 읽을 수 있는 문장으로 함께 반환합니다. 근거가 약한 신호가 점수를 끌어올리지 않도록 리뷰 검증 임계값도 적용했습니다.

### VeRoRo — 개인화 분석 + 제품 DB + 운영자 콘솔

반려동물의 프로필(알레르기·건강 우려)을 기준으로 사료 원재료를 분석해 **적합도와 등급**으로 환산해 주는 모바일 우선 서비스입니다. 사용자 서비스와 별도 인증 체계를 가진 관리자 콘솔 10개 화면이 같은 데이터베이스를 공유하며, 관리자가 등록·검수한 제품이 사용자 화면 노출과 분석 입력에 그대로 반영됩니다.

**MELIQ 직접 관련** — Product DB, 규칙 기반 분석 엔진, 위험 성분 필터, 적합도 점수, 검수 상태·정보 완성도 표기, 감점 사유 문장화, 결과 저장까지 MELIQ가 요구하는 구성요소 대부분이 동일한 형태로 구현되어 있습니다. 도메인만 K-beauty가 아닌 펫푸드일 뿐, 구조는 사실상 같습니다.

### 세탁 서비스 앱 (A.care) — 운영 가능한 B2B SaaS

거래처용 Flutter 주문 앱과 공장 운영진용 관리자 웹(12개 화면), Express API 서버, PostgreSQL(29 테이블·24단계 마이그레이션)을 OpenAPI 공용 계약으로 묶은 B2B 시스템입니다. 주문 상태 5종과 이행 단계 4종을 별도 축으로 분리하고, 모든 상태 변경이 행 잠금·버전 확인·전이 검증을 거치는 단일 통로를 지나도록 설계했습니다.

**MELIQ 직접 관련** — 역할 6종 × 권한 31종 매트릭스를 서버 정본으로 두고, 개인정보 대량 반출 권한을 단순 조회 권한과 분리했습니다. 상태·이력 관리와 관리자 권한 분리는 MELIQ의 Admin Dashboard와 결과 History 요건에 그대로 적용됩니다.
