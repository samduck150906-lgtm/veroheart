## 운영 반영 순서 및 남은 출시 검증

1. 운영 DB/Storage 복구 수단을 확인하고 현재 마이그레이션 원장을 대조합니다. 기존 프로젝트에는 `supabase/migrations`의 미적용 forward migration만 적용합니다. 로컬 부트스트랩용 가드는 운영에 적용하지 않습니다.
2. 새 scan/catalog/account/search 마이그레이션을 순서대로 검토·적용합니다. 사진 버킷 비공개 전환과 권한 변경은 구 버전 클라이언트 동작에 영향을 주므로 앱/서버 배포를 함께 조율합니다. 공개 설정으로 되돌리는 방식은 복구 수단으로 사용하지 않습니다.
3. `account-manage`, `admin-auth`(410 폐쇄 버전), `admin-write` Edge Functions를 배포합니다. 기존 관리자 엔드포인트는 코드만 삭제하여 구 배포가 남지 않도록 주의합니다.
4. Netlify 서버 환경에 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `GEMINI_API_KEY`, 강한 `SCAN_RATE_LIMIT_SECRET`을 설정합니다. 프런트는 `VITE_SUPABASE_URL`, 공개 anon key, `VITE_PUBLIC_APP_URL`, 네이티브 `VITE_API_BASE_URL`, 실제 개인정보 문의 주소를 설정합니다. 필요할 때만 추가 출처를 허용합니다.
5. Supabase Auth의 공개 HTTPS callback/recovery URL과 `com.veroro.app://auth/callback`을 검토하고, 실제 SMTP의 가입·복구 메일 전달을 확인합니다. 네이티브 소셜 로그인은 필요한 제공자와 정책 검증 전 활성화하지 않습니다.
6. Netlify 앱과 Functions를 함께 배포한 다음 테스트 계정으로 가입→복구→사진 등록/교체→제품 스캔→중복 검토→탈퇴를 검증합니다. 익명/다른 사용자의 사진·상태 변경 거부, background 작업, 30일 정리 스케줄도 실제 서비스에서 확인합니다.
7. 공식 제품 import preview를 다시 생성·검토한 후 적용하고 공개 개수/중복/종 구분/처방식 안내를 확인합니다. 검토 6개는 자동 생성하지 않습니다.
8. Android 실제 기기, iPhone 실제 기기에서 카메라와 인증 복귀를 확인합니다. Xcode 빌드/서명, Android 릴리스 키와 AAB, App Store/Play 개발자 계정·개인정보/데이터 안전성·삭제 URL 등 제출 항목은 운영자가 준비해야 합니다.

## 로컬 검증의 범위

`npm run check`는 lint, Vitest 전체, 수집기 테스트, 빈 DB SQL 재생, scan/account/catalog 실제 PostgreSQL 권한 회귀, 앱·Functions 타입 검사와 프로덕션 빌드를 수행합니다. `npm audit`는 현재 레지스트리에서 알려진 취약점 검증이며 모든 보안 문제 부재의 보증은 아닙니다.

SQL 테스트는 PGlite의 PostgreSQL에서 Supabase 소유 auth/storage 테이블 최소 모형을 사용합니다. Hosted Auth/Storage HTTP 및 전체 Supabase Docker 서비스를 실행한 테스트와 구별해야 합니다. Windows에서 Android 디버그 및 서명 전 릴리스는 빌드 가능하지만 iOS 컴파일은 macOS CI/Xcode 결과로 확인해야 합니다. 테스트용 APK는 출시 서명된 스토어 파일이 아닙니다.

## 후속 수정: 홈 추천의 90점 기준

기존 홈은 초기 제품 목록에서 최근 본 제품을 제외하고 점수순으로 3개를 채웠습니다. 최소 점수 조건이 없어 0점 제품도 포함됐고, 초기 경량 목록에는 점수 검증에 필요한 원료 정보가 없었습니다.

- 실제 등록된 동물의 프로필로 원료 분석이 가능한 제품만 평가하며, 궁합 점수 90점 이상만 최대 3개 표시합니다. 종이 불명확하거나 맞지 않는 제품, 미확인 원료가 있는 제품, 수의사 상담이 필요한 제품은 제외합니다.
- 공개 검색 페이지의 현재 원료·영양 정보를 읽어 상세 화면과 같은 점수를 계산합니다. 적격 제품 3개를 찾거나 해당 종의 목록을 모두 확인하면 조회를 마칩니다. 전체 카탈로그 최고 3개라는 의미는 아닙니다.
- 기준 충족 제품이 없으면 빈 상태를 안내하고 낮은 점수로 채우지 않습니다. 조회 실패는 별도 오류·재시도 화면을 제공합니다. 프로필 변경 시 이전 점수를 즉시 숨기고 늦게 도착한 이전 응답을 무시합니다.
- 최근 본 상품 영역은 유지합니다. 이미 본 제품도 90점 기준을 충족하면 추천에 포함될 수 있습니다. 숫자는 적합 확률이 아닌 참고 점수로 표기합니다.
