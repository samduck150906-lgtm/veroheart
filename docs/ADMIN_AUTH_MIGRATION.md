# 관리자 인증 전환 계획 (ADMIN_AUTH_MIGRATION)

작성일: 2026-07-28
대상: `veroro-admin.netlify.app` (`/admin` 라우트) · `supabase/functions/admin-write`

---

## 1. 현재 구조 (사실)

| 요소 | 구현 |
|---|---|
| 자격증명 입력 | `AdminAuthGuard` 에서 아이디·비밀번호 입력 |
| 토큰 생성 | `btoa("id:pw")` — **암호화가 아니라 인코딩** |
| 보관 | `sessionStorage` (`vh_admin_auth`, `vh_admin_auth_issued_at`) |
| 전송 | `x-admin-token` 헤더 (HTTPS) |
| 검증 | Edge Function 이 SHA-256 해시를 화이트리스트(3개)와 비교 |
| DB 접근 | 검증 통과 시에만 service_role 클라이언트 사용 |
| 인가 범위 | action 단위 화이트리스트 + 컬럼 화이트리스트 |

**중요:** service_role 키는 서버 환경변수에만 있고 클라이언트 번들에 포함되지 않는다.
따라서 토큰이 유출돼도 RLS 를 직접 우회할 수는 없고, `admin-write` 가 허용한 action 만 수행된다.

## 2. 이번 작업에서 적용한 보완 (완료)

- **세션 TTL 8시간** — `lib/adminSession.ts`. 발급 시각이 없거나 만료된 토큰은 자동 폐기.
  (기존에는 탭이 열려 있는 한 무기한 유효했다.)
- **로그아웃 완전 삭제** — 토큰과 발급 시각을 함께 제거.
- **계정 열거 방지** — 로그인 화면에서 허용 계정 아이디 목록(`rumi / young / jeong`) 표기를 제거하고,
  실패 메시지를 아이디 존재 여부와 무관한 단일 문구로 통일.
- **인증 실패 레이트리밋** — Edge 인스턴스 로컬로 5분/10회 초과 시 429.
- **인증 우선 순서 고정** — 모든 action 은 토큰 검증 이후에만 실행된다.
- **감사 로그** — `admin_audit_log` 에 actor(아이디만) · action · 대상 · 시각 기록.
  비밀번호는 저장하지 않는다(`actorFromToken` 이 아이디만 추출).
- **입력 검증 서버화** — 컬럼/설정 키 화이트리스트, UUID 형식 검증, 이미지 매직 바이트 검증.

## 3. 남아 있는 한계 (알려진 위험)

1. **토큰이 곧 자격증명이다.** `btoa("id:pw")` 는 되돌릴 수 있으므로, 토큰 유출 = 비밀번호 유출이다.
2. **서버 측 세션 무효화 수단이 없다.** 비밀번호를 바꾸려면 Edge Function 의 해시 상수를 고쳐 재배포해야 한다.
3. **레이트리밋이 인스턴스 로컬이다.** Edge 인스턴스가 여러 개면 시도 횟수가 인스턴스별로 계산된다.
4. **계정 추가·회수에 배포가 필요하다.** 관리자 3명이 코드 상수로 고정돼 있다.

## 4. 권장 전환안 (다음 단계)

### 4-1. 1순위 — Supabase Auth 기반 관리자 role

1. 관리자 계정을 Supabase Auth 사용자로 생성한다(이메일 + 비밀번호).
2. `app_metadata.role = 'admin'` 을 부여한다(service_role 로만 설정 가능).
3. `admin-write` 의 `verify_jwt` 를 `true` 로 바꾸고, 요청의 JWT 에서 role 을 확인한다.
4. 프론트는 `supabase.auth.signInWithPassword` 를 쓰고, 자체 토큰 저장을 없앤다.

**얻는 것:** 토큰 만료·갱신·서버 측 무효화, 비밀번호 재설정, MFA, 계정 추가/회수가 배포 없이 가능.

### 4-2. 2순위 — 단기 서명 토큰

Supabase Auth 도입이 어렵다면, 로그인 시 서버가 HMAC 서명한 15분짜리 토큰을 발급하고
클라이언트는 그 토큰만 보관한다. 비밀번호는 로그인 요청 1회에만 실린다.

### 4-3. 공통 후속 작업

- 레이트리밋을 DB 또는 KV 기반으로 옮겨 인스턴스 간 공유.
- `admin_audit_log` 열람 화면(관리자 콘솔) 추가.
- CORS `CORS_ALLOWED_ORIGINS` 를 관리자 호스트로 명시 지정(현재 미설정 시 `*`).
