# 사용자 제보 후속 수정

대상: PR #114의 기존 출시 보완 작업에 이어 접수된 실제 사용 문제. 아래 내용은 소스 수정과 검증 결과이며 운영 배포·DB 반영·스토어 제출 완료를 의미하지 않습니다.

| 기록 추가 버튼 중복 | 달력·주간·목록 각각에 일관된 기록 추가 버튼 하나를 둡니다. |
| 추천 키워드·제품 수 부족 | 실제 카탈로그 브랜드·제품명·지원 건강 항목에서 키워드를 만듭니다. 힐스 공식 출처 90개를 추가 준비했습니다. 운영 제품 증가는 아직 적용하지 않았습니다. |

| 관리자 분류 오류·숨긴 제품 재노출 | main_category와 product_type을 함께 검증·정규화합니다. 비노출 조건을 삭제하던 조회 폴백을 폐쇄하고, 최신 응답만 반영하며 캐시·추천·찜 목록도 재검증합니다. 재수집은 원본 출처의 안정된 식별자로 기존 제품을 찾아 숨긴 제품의 복제본을 생성하지 않습니다. |

## 바코드의 범위

바코드는 제품 식별자입니다. 원료·영양 정보가 번호 자체에 들어 있지는 않습니다. 앱 공개 카탈로그에 실제 제품과 번호의 연결이 있어야 상세 화면으로 연결됩니다. 정상 조회에 일치하는 제품이 없으면 번호를 보존해 등록 화면으로 이동합니다. 다른 포장 단위를 나타내는 0이 아닌 GTIN-14 앞자리는 같은 제품으로 합치지 않습니다.

## 추가 제품 데이터

공식 출처: [힐스 반려견](https://www.hillspet.co.kr/dog-food), [힐스 반려묘](https://www.hillspet.co.kr/cat-food).

- 준비한 힐스 90개: 강아지 30, 고양이 59, 공용 1. 서로 다른 URL에서 같은 이름인 k/d 2건은 제외했습니다.
- 기존 로얄캐닌 198개와 합쳐 288개 고유 제품의 출처 데이터가 있습니다. 2026-10-26 읽기 전용 카탈로그 스냅샷과 비교한 힐스 preview는 신규 후보 90개입니다. 현재 운영 수량을 뜻하지 않습니다.
- 공식 사이트에서 확인한 이름·출처·대상·상담 필요 여부만 사용하며 바코드·원료·영양 수치는 추정하지 않습니다. 직접 HTTP 접근이 거절된 부분은 우회하지 않았으며 공개 웹으로 확인한 범위만 담았습니다.
- import는 기본 미리보기입니다. 제품 이름이 변경돼도 기존 manufacturer observation으로 연결하고, 서로 다른 기존 제품에 연결되면 검토 대상으로 남깁니다. 숨김·검토 완료 데이터는 덮어쓰지 않습니다.

## 검증과 적용 범위

로컬 전체 검사: Vitest 253개 파일 / 1,600개 테스트, importer 7개, SQL bootstrap 및 scan/account/catalog 권한·경합 검사, lint·앱/서버 타입·프로덕션 빌드 통과. 바코드는 실제 픽셀(EAN-13, EAN-8, UPC-A, UPC-E 양쪽 번호 체계), 회전, 네이티브 디코더 실패 전환 및 조회 경합을 검사했습니다.

독립 리뷰에서 캐시의 오래된 응답, foreground/background 로딩 경합, 바코드 캐시 우회, 중복 조회 오류 안내, 이름 변경 후 재수집 중복을 추가 발견해 수정하고 회귀 검사로 확인했습니다. 힐스 재수집 SQL은 PGlite에서 291개 출처 관측 / 288개 고유 제품, 권한 거부, 숨긴 제품 이름 변경 후 재실행 및 식별 충돌까지 재검증했습니다.

로컬 브라우저에서 상시 성향 테스트 문항 이동, 독립 다이어리 진입 및 비교 경로의 탐색 리다이렉트를 확인했습니다. 로컬 미연결 환경의 검색 결과 수는 운영 데이터 검증으로 취급하지 않습니다. 실제 iPhone/Galaxy 카메라·실서비스 가입/복구/등록요청 완료 검증은 별도입니다.

운영에는 프런트 변경 외에 admin-write 배포와 20261026180000 분류 정규화, 20261026190000 공식 import 보완 마이그레이션이 필요합니다. 제품 후보 import는 분류·중복·출처 preview 검토 후 별도로 수행해야 합니다. 기존 PR의 계정·Storage·스캔 보안 마이그레이션 순서도 지켜야 합니다.

## 미로그인 궁합 표시 후속 수정

- 미로그인 또는 동물 미등록 상태의 홈 추천 자리에 등록 안내 버튼을 표시합니다. 현재 문구는 아래 존댓말 통일 기준에 따라 ‘우리 아이를 등록하고 궁합을 확인해 주세요.’입니다.
- 미로그인 사용자는 로그인 후 동물 등록 화면으로, 로그인했지만 동물이 없는 사용자는 등록 화면으로 바로 연결합니다.
- 검색 제품 카드의 개인 궁합 문구와 제품 상세의 적합도 퍼센트·개인 결론은 로그인한 실제 동물 프로필이 있을 때만 표시합니다. 공개 원료 정보와 제품 자체의 원료 평가는 계속 볼 수 있습니다.
- 로그아웃 시 프로필 데이터가 잠시 남아 있거나 추천 요청이 뒤늦게 끝나도 이전 동물의 궁합을 표시하지 않습니다.
- 로컬 브라우저에서 미로그인 안내 표시와 로그인 화면 연결을 확인했습니다. 로그인 후 등록 목적지는 라우터 상태 회귀 테스트로 검증했으며 실제 계정 로그인은 수행하지 않았습니다.
- 최종 전체 검사: Vitest 255개 파일 / 1,607개 테스트, 수집기 7개 테스트, SQL/RLS 검사, lint·앱/서버 타입·프로덕션 빌드 통과.

이번 후속 수정은 프런트엔드 변경이며 새 DB 마이그레이션은 없습니다. 기존 PR 전체의 운영 배포는 별도입니다.

## 계정 가입 정보 표시 후속 수정

마이페이지의 ‘계정·설정’을 누르면 가입 정보 화면에서 다음 항목을 확인합니다.

- 닉네임 / 이름: 저장된 public.users.nickname을 우선 표시하고, 이전 가입 방식에서 프로필 행이 없으면 인증 계정의 nickname·name·full_name을 확인합니다.
- 이메일 주소: 현재 로그인한 인증 계정의 이메일을 표시합니다.
- 휴대폰 번호: 인증 계정 또는 계정 메타데이터에 설정된 번호를 표시합니다. 없으면 ‘등록된 휴대폰 번호가 없습니다’로 안내합니다.

이번 변경은 정보 확인 기능이며, 닉네임·번호 편집이나 새 번호 등록 절차는 추가하지 않습니다. 계정 ID 검증, 계정 전환 시 이전 응답 무시, 조회 실패와 미등록 구분 및 재시도를 검사했습니다. 쿼리는 본인의 id,nickname만 읽으며 새 DB 마이그레이션은 없습니다.

검증: 관련 22개 테스트 및 전체 Vitest 256개 파일 / 1,614개 테스트, SQL/RLS·lint·타입·빌드 통과. 별도 읽기 전용 검토에서 추가 결함이 보고되지 않았습니다. 실제 컴포넌트를 예시 데이터로 브라우저에 렌더링해 화면을 확인했으며, 실제 계정 로그인·운영 데이터 변경은 수행하지 않았습니다.

## 검수 대기 제품 공개 차단 후속 수정

검수 대기 제품의 공개 차단이 선택적인 시스템 설정에만 의존하던 경로를 제거했습니다. 이제 공개 조회는 노출 설정과 검수 상태를 함께 확인합니다.

| 제품 상태 | 노출 설정 | 앱 공개 여부 |
| --- | --- | --- |
| 검수 대기·상태 미지정·알 수 없는 상태 | 켜짐 또는 꺼짐 | 항상 비공개 |
| 검토됨 | 켜짐 | 공개 대상. 단, ‘검수 완료 제품만 노출’ 시스템 설정을 켜면 비공개 |
| 검수 완료 | 켜짐 | 공개 대상 |
| 모든 검수 상태 | 꺼짐 | 비공개 |

- 홈·탐색·검색·브랜드·제품 상세·바코드·찜·최근 본 제품·기록 추가용 제품 검색에 동일한 조건을 적용합니다. 조회 실패 때 검수 조건을 빼고 다시 읽는 경로는 없습니다.
- DB의 공개 권한에도 필수 조건을 적용합니다. 다른 허용 정책이 추가돼도 검수 대기 제품을 공개하지 못하도록 제한 정책을 함께 두고, 원료·영양·분석·라벨·별점 조회에도 부모 제품의 공개 조건을 적용합니다.
- 관리자 목록과 수정 창은 ‘노출 설정’과 실제 공개 조건을 구분합니다. 검수 대기 제품의 설정을 켜거나 저장해도 ‘공개 완료’로 잘못 안내하지 않습니다. 기존 설정의 명칭은 ‘검수 완료 제품만 노출’로 바꿨습니다.
- 검색엔진용 제품 메타데이터와 사이트맵도 같은 검수 조건을 적용하고 응답의 재사용 캐시를 끕니다.
- 기존 제품의 검수 상태·노출 설정은 그대로 보존합니다. 관리자는 검수 대기 제품을 계속 조회·검수할 수 있으며, 사용자의 비공개 기록은 삭제하지 않습니다.
- 독립 리뷰에서 공개 차단 후 관리자 편집이 원료·영양을 빈 값으로 읽을 수 있는 경로를 발견해 보완했습니다. 관리자 인증을 거쳐 제품과 편집 자료를 함께 조회하고, 불완전한 조회·로딩 중 저장을 차단합니다. 이름만 수정해도 기존 자료가 유지되며, 창을 닫은 뒤 도착한 이전 응답은 무시합니다.
