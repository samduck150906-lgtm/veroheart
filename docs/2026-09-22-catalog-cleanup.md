## 왜 했나

옛 프로젝트에서 넘어온 것은 제품 행뿐이었다. 원재료는 7개 제품분, 영양정보는 0건이다.

유입분(2026-03-29 18개 · 04-02 173개 · 05-16 818개)은 2026-04-02 에 만들어진 이 프로젝트보다
앞선 생성일을 달고 들어왔다. 타임스탬프를 보존한 이전이라는 뜻이고, 곧 **옛 프로젝트에도
원재료·영양정보는 없었다**는 확인이기도 하다.

## 무엇을 했나

제품을 지우지 않았다. `is_visible = false` 로 노출만 내렸다.

- **A. 유입분 중 원재료 없는 제품 1,002개** — 분석할 수 없는 제품이 카탈로그의 대부분을
  차지해 검색 결과를 덮었다. 원재료가 붙는 대로 다시 켜면 된다.
- **B. 이름이 같은 사본 27개** — 그룹마다 `ingredient_count` 가 가장 많은 하나만 남기고
  나머지를 내렸다(동률이면 먼저 만들어진 것). A 를 적용한 뒤의 노출 제품 기준이다.

## 되돌리는 법

정리 직전 이 DB에 숨겨진 제품은 **0개**였다. 그래서 지금 숨김 상태인 1,029개가 이번 변경분과
정확히 일치한다.

```sql
-- 전부 되돌리기 (2026-09-22 정리 이전 상태로)
update public.products set is_visible = true where is_visible = false;
```

```sql
-- A 만 되돌리기
update public.products set is_visible = true
where is_visible = false
  and created_at::date in ('2026-03-29','2026-04-02','2026-05-16')
  and ingredient_count = 0;
```

원재료를 채우면 `ingredient_count` 트리거가 따라 오르고, 그 제품을 다시 노출로 바꾸면
`has_ingredients` 정렬에 따라 목록 앞쪽으로 올라온다.
