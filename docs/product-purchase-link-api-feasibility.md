# 판매 상품·옵션 API 이용 가능성 결정표

조사일: 2026-11-01 KST. PR #115는 Draft·미병합이며 운영 미적용이다.
신규 API 호출·계정 연결·key 확인·운영 DB 접근은 하지 않았다. audit 조사는 재실행하지 않았다.

## 1. 결정

**권고안 하나: 구매 CTA를 보류하고 성분 판정 서비스와 출시 의존성을 분리한다.**

현재 베로로가 정확한 타 판매자 SKU를 확인할 수 있다고 입증된 API 경로는 없다.
Partners 검색 연동 코드는 있지만 계정의 현재 API 이용 자격/실제 원본 응답은 미확인이고,
현 코드의 네 필드만으로 맛·용량·포장·선택 옵션을 보장할 수 없다.
WING 상품 조회는 명세에 상세 필드가 있어도 다른 업체 상품 조회를 거부하므로 일반 상품 카탈로그의 대안이 아니다.
이것은 향후 가능한 모든 제휴 데이터를 부정하는 결론이 아니라, 현재 확보한 권한/근거로 출시할 수 없다는 판단이다.

사람의 브라우저/포장 검토는 이후 소수 제품에 한해 검토 가능하지만, 정상 근거 수집/승인 경로와 담당자가
준비되지 않은 상태에서 전 상품 수동 갱신을 사업 전제로 삼지 않는다. 이번에 수동 운영 출시는 권고하지 않는다.
정보가 부족한 근거로 재확인 수집기나 실응답 fixture를 만들지 않는다.

## 2. API 종류·계정 자격·권한

| 경로 | 코드/공식 문서로 확인한 사실 | 베로로의 실제 이용 가능성 |
| --- | --- | --- |
| Partners affiliate 검색 | 현재 코드의 GET `/v2/providers/affiliate_open_api/apis/openapi/v1/products/search`; Partners HMAC key 사용. 관리자 `x-admin-token`은 베로로 호출 인증이며 판매처 API 권한과 별개 | 연동 코드 존재만 확인. 현재 계정 승인/key 유효성/호출 성공은 이번에 확인하지 않음 |
| Partners API 자격 | 공식 보존 이용 가이드(2024년판)는 최종 승인과 API 이용 자격을 구분 | 가입만으로 이용 가능하다고 판단하지 않음. 과거판 가이드를 현재 계정 승인 증거로 사용하지 않음 |
| Partners 상세 개발 문서 | 공식 Open API 진입 페이지는 JS 앱으로 이 조사 경로에서 응답 스키마를 읽을 수 없었음 | 옵션 필드가 API 전체에 절대 없다고 단정하지 않음. 계정 소유자가 이미 볼 수 있는 최신 문서가 있으면 key 없는 필드 명세만으로 재판정 가능 |
| WING 판매자 상품 조회 | GET `seller-products/{sellerProductId}`; WING 판매자 계정에서 발급한 별도 API key 체계 | Partners key와 교환 사용하지 않음. 공식 오류 명세에 다른 업체 상품 조회 거부가 명시됨. 타 판매자 상품의 일반 조회 수단으로 채택하지 않음 |
| 제조사/판매자 제공 feed | 이번에 이용 가능한 계약·샘플·명세를 확보하지 않음 | 향후 별도 허용 범위와 SKU 필드를 입증할 때만 새로운 대안으로 검토. 존재/권한을 가정하지 않음 |

공식 근거:
- [WING 상품 조회](https://developers.coupang.com/ko/api/products/querying-product): 오류 사양의 타 업체 상품 조회 제한,
  필드 표/응답 예시의 구분을 확인했다. 이번에 운영 호출로 거부를 재현한 것은 아니다.
- [WING 준비/ID 안내](https://developers.coupang.com/ko/getting-started/coupang-open-api): 계정/key 체계 및 ID 의미.
- [Partners 공식 Open API 진입](https://partners.coupang.com/#help/open-api): JS 페이지여서 상세 문서 접근 한계.
- [Partners 공식 보존 가이드, 2024년판](https://partners.coupangcdn.com/partners-guide/partners-guide-20240716100922.pdf):
  승인/API 구분의 과거 공식 안내. 최신 계정 자격 확인을 대체하지 않는다.

계정 신규 연결이나 비밀키 제출이 필요한지 시험하지 않았다. 판매자가 직접 제공한 자기 상품의 허용된
자료가 생기면 별도 검토할 수 있으나, 그 가능성을 타 업체 WING 조회 권한으로 확대 해석하지 않는다.

## 3. 필드별 증거 매트릭스

표의 `현 코드`는 소비하도록 작성된 타입/로직이지 **실제 응답으로 확인됨**이라는 뜻이 아니다.
Partners 공식 상세 응답 명세는 이번에 읽지 못했다. WING 열은 허용된 자기 업체 조회의 문서상 정보이며,
베로로에 제공됐거나 타 판매자 상품에 사용할 수 있다는 뜻이 아니다.

| 필요한 사실 | Partners 현 코드 | Partners 공식 상세 명세 | 보존된 실제 API 원응답 | WING 공식 명세/예시 |
| --- | --- | --- | --- | --- |
| 브랜드 | 전용 필드 소비 없음 | 미확인 | 미확인 | `brand`, `brandId` 문서상 존재 |
| 제품군/라인 | `productName` 문자열뿐; 라인 분리 없음 | 미확인 | 미확인 | `productGroup`, `generalProductName` 존재; 제품군이 라인 동일성을 보장하지 않음 |
| 맛/단백질원 | 전용 필드 소비 없음; 제목에서 추정 금지 | 미확인 | 미확인 | 범용 `attributes`의 값으로 표현될 수 있으나 해당 상품 제공/완전성 미확인 |
| 단위 용량/중량 | 전용 필드 소비 없음 | 미확인 | 미확인 | 옵션/고시 내용 후보. 표준화된 모든 식품의 단위 용량 제공을 보장하지 않음 |
| 포장 수량/세트 구성 | 전용 필드 소비 없음 | 미확인 | 미확인 | 옵션 값/내용 후보. 예시 `unitCount`를 포장 수량으로 확정하지 않음 |
| 노출 상품 ID | `productId` 소비/동등 비교 | 미확인 | 미확인 | 시작 안내에서 의미 정의. 등록상품 ID와 다름; 결합/분리로 변경 가능 |
| 등록상품 ID | 소비 없음 | 미확인 | 미확인 | `sellerProductId` 요청/응답; 노출 상품 ID로 대체 불가 |
| 아이템 ID | `itemId` 소비/검사 없음 | 미확인 | 미확인 | `items[].itemId`는 응답 예시에 존재; 모든 실제 응답 제공 보장은 미확인 |
| 옵션 ID | `vendorItemId` 소비/검사 없음 | 미확인 | 미확인 | `items[].vendorItemId` 명세에 존재; 임시저장 상태 null 가능 |
| 판매 제안 식별 | 별도 offer 식별/버전 없음 | 미확인 | 미확인 | vendorItemId는 옵션 ID. 별도 가격 제안/견적 버전 ID를 제공한다고 해석하지 않음 |
| 판매 URL | `productUrl` 소비 | 미확인 | 미확인 | 이 경로에서 베로로의 정규화된 구매 URL 제공을 확인하지 않음 |
| 가격 | `productPrice` 소비; productId만 일치시 제안 | 미확인 | 미확인 | 가격 필드 존재와 해당 SKU 대응 승인은 별개 |

WING 속성은 빈값/시스템 추출 값일 수 있다. 필드 이름이 있다고 맛·용량·구성이 완전하다고 간주하지 않는다.
문서 예시의 합성 상품을 실응답 증거로 사용하지 않았다.

현재 초안의 `seller_product_id`는 노출 `productId`, `seller_item_id`는 `itemId`,
`seller_offer_id`는 `vendorItemId`를 저장한다. 마지막 이름은 내부 명칭일 뿐 외부의 별도 판매 제안 ID를
확인했다는 뜻이 아니다. WING `sellerProductId`/`sellerProductItemId`를 이 필드에 임의 대입하면 안 된다.

## 4. 기존 응답 자료 검토 범위와 한계

- 현재 구현에서 원본 response는 `data.productData`로 파싱하고, 네 필드를 소비한다.
  원본을 보존하는 기능/fixture는 이 경로에 없다. 확인 가능한 저장소·기존 복구 자료 목록에서
  해당 Partners 요청의 출처가 확정된 원문 응답 파일을 확보하지 못했다. 다른 위치의 존재까지 부정하지 않는다.
- 원래 작업공간의 추적된 `src/data/coupang_products.json`은 20행 정규화 배열이다.
  필드는 brand/name/price/image_url/product_type/main_category/target_pet_type/product_url/source이며
  Partners response envelope/상품·옵션 ID가 없다. 따라서 브랜드 값이 있다는 이유로 API가 브랜드를 반환했다고 하지 않는다.
  원문 생성/수집 방식과 현재 API 자격을 이 파일만으로 입증하지 않는다. 내용/실상품 식별정보는 이 문서에 복사하지 않았다.
- 기존 Dashboard 결과는 DB에 저장된 제품/관찰 자료이며, 외부 API 원응답의 필드·현재 권한 증거가 아니다.
- 앱의 정상 관리자 인증 성공 기록은 베로로 관리자 API 접근 증거일 뿐 Partners/WING 승인 증거가 아니다.
- 코드 주석의 단건 조회 미지원 설명은 코드 작성 시 설명이다. 공식 최신 명세를 확인하지 못한 상태에서
  Partners의 모든 기능에 대한 확정적 부재 주장으로 사용하지 않는다.

신규 비식별 실응답 fixture는 만들지 않았다. 추후 기존의 허용된 원응답이 실제로 확보되면,
key/header/계정/추적 값/실제품 정보를 제거하고 필드 구조·null/누락·옵션 대응 관계를 유지한 fixture를
별도 검토한다. 합성 응답을 기존 API 성공 응답으로 표현해서는 안 된다.

## 5. 구매 연결과 성분 판정의 의존성 분리 (설계, 코드 변경 없음)

| 개발/출시 단위 | 필요한 근거 | 이번 결정 |
| --- | --- | --- |
| 성분 판정·제품 검색/상세·기존 건강 판단 | 기존 제품/성분 근거와 해당 기능의 검증 | 판매처 API/SKU 연결을 필수 입력으로 추가하지 않고 개발 지속 |
| 구매 연결 backend 초안 | 새 DB 테이블/RPC/권한·근거·삭제 정책·실 Supabase 검증 | PR #115 Draft 유지. 판매처 API가 생겼다는 가정으로 배포하지 않음 |
| 공개 구매 CTA | 유효한 맛·용량·포장·옵션 대응 및 운영 재확인 수단 | 현재 보류. legacy coupang_link, 검색 링크, 첫 검색 결과를 대체 연결로 사용하지 않음 |
| 가격 표시/연계 | 해당 옵션의 승인된 가격 근거와 독립 최신성 | 검색의 productId 일치 가격을 해당 판정 SKU의 확정 가격으로 승격하지 않음 |

코드 점검상 현재 공개 `Detail`/`ProductCard`/`ProductRow`는 신규 구매 RPC를 호출하지 않는다.
후속 구매 모듈의 빈 결과·외부 실패는 구매 영역만 생략하고 성분 판정 실패/점수 감소로 전파하지 않는 계약을 둔다.
구매 모듈을 비활성화해도 원본 링크/관찰은 보존하고 관리자 참고 링크와 검증된 구매 연결은 구분한다.
이것은 이번 실행에서 feature flag나 운영 노출 값을 바꿨다는 뜻이 아니다.

주의: PR #115의 `deleteProduct`는 새 원자적 DB 함수에 의존한다. 판매 API와 독립적이라고 해서 DB 미준비 상태의
admin-write만 부분 배포해도 된다는 뜻은 아니다. 관련 배포 순서는 기존 문서대로 유지한다.
audit 등 공통 출시 검사를 우회하거나 낮추는 방식으로 성분 서비스 출시를 분리하지도 않는다.

## 6. 만료와 재개 조건

24시간은 현재 구현의 임시 상한이다. 이번에 연장하거나 확정 사업 정책으로 승격하지 않는다.
근거가 없거나 만료되면 구매 연결 없음이 안전한 결과이며, URL200·ID 존재·재고 확인으로 시각을 연명하지 않는다.
성분 판정에는 이 24시간을 적용하지 않는다.

현재 필요한 소유자 결정/준비는 다음 두 가지 이내다.

1. 구매 CTA 보류 및 성분 판정 개발 독립 진행을 채택할지 결정한다. 추가 계정/key 준비는 이 경로의 필수 조건이 아니다.
2. 구매 기능을 재개하려는 경우에만, 이미 정상 계정에서 볼 수 있는 최신 Partners 필드 명세나 보존된 원응답의
   비민감 구조/승인 여부를 제공한다. 비밀번호/key/토큰은 제공하지 않는다. 새 호출·새 계정 연결도 요구하지 않는다.
   원문이 없으면 판매자가 적법하게 제공할 수 있는 SKU 명세/자료가 있는지 먼저 확인한다.

그 새 증거가 없다면 WING 타 업체 조회·기존 보류 링크를 반복 조사하지 않는다.
사람 검토 파일럿을 이후 선택한다면 정상 저장/감사 경로, 실제 선택 옵션과 포장 근거, 검토 담당자,
상한 내 처리 가능성이 별도로 준비돼야 한다. 이번에는 수동 승인·관찰 저장·CTA를 활성화하지 않는다.
